# v0.3.2

A hierarchical EDIF netlist can now be read whole. Until this release every read stopped at the
design's top cell, so an aggregator export with its schematic in fifty blocks read as a handful of
parts, and every count, check and diff covered the top sheet alone. Flattening is off by default,
because it renames every net inside a block, and it can be asked for from the CLI, the wire, a
design's `design.yaml` or the viewer. The release also fixes four verdicts the KiCad comparison
turned up, skips most of a KiCad board's footprint graphics while parsing rather than after, and
adds the security scanners to the gate. Nothing is removed or renamed, so it is a patch release.

## Added

- **`--flatten-hierarchy` reads a hierarchical EDIF netlist whole** (PR 1101). The reader walks
  from the top cell into every block it places. A net crossing a block's port joins its parent's
  and keeps the parent's name. A net inside a block keeps its own name when no other net carries
  it, and is otherwise named by the block's path (`/A1/MID`). A part inside a block placed more than
  once carries its path (`B2/R1`), so two placements are two sets of parts. Parts sharing a
  designator stay one component across sheets, so a multi-gate part split over two sheets is still
  one part. A flat netlist reads identically with the flag on. On the wire it is
  `Snapshot.flatten_hierarchy`, and the CLI note on a partial read names the flag.
- **`agni trial` and the Python client honour it** (PR 1106). `Client.ingest` takes
  `flatten_hierarchy`, and the CLI transport passes `--flatten-hierarchy` to every command that reads
  the design. Before this, the CLI transport dropped the field, so one definition read every block
  over Connect and the top cell over the CLI.
- **A design can declare `flatten_hierarchy: true` in its `design.yaml`** (PR 1109), which the CLI,
  a server and the browser all honour with no flag. A release older than this one refuses a
  `design.yaml` carrying the key, as it refuses any key it does not know.
- **The viewer's hierarchy strip offers Read every block** (PR 1109). It re-opens the page with
  `?flatten=1`, and every question the page asks then reads the design whole, in the browser engine
  and against a server.
- **Security scans** (PR 1100). `make lint`, `vulncheck`, `seccheck`, `secrets` and `audit` run
  staticcheck, govulncheck, gosec and gitleaks at pinned versions. `lint`, `seccheck` and `secrets`
  are in `testall`, `vulncheck` runs weekly and on each tag, and OpenSSF Scorecard runs on its own
  workflow. Integer narrowings now go through `core/num`, which saturates rather than wraps, and
  both servers set a `ReadHeaderTimeout`. `SECURITY.md` says how to report a vulnerability.
- **Synthetic reproducers for issues 1085 to 1098** (PR 1099) under
  `cmd/agni/testdata/github-issues/`, each with the behaviour it expects.

## Changed

- **A KiCad or gEDA pin typed tri-state, open-collector or open-emitter keeps its type** (PR 1108).
  They read as unspecified before, so `unspecified-pin-with-driver` reported a pin whose symbol
  declares a type. Each counts as driving a net, and none as a hard driver for
  `output-output-conflict`.
- **A power net's supply pins need a power source** (PR 1108). On a net carrying a power symbol only
  a power output or power flag feeds them now, as KiCad's ERC holds, so a ground fed by signal pins
  alone fails `power-input-not-driven`. On any other net any driver still counts.
- **No rule judges a do-not-populate part** (PR 1108). The eleven rules about a part's own rating or
  orientation leave an unfitted part out, and `floating-input` counts the assembled board's pins, so
  an input whose only pull is unfitted fails.
- **The tutorial gateway's planted copper faults are near misses KiCad can check** (PR 1108), so
  KiCad's DRC reports the same nine pairs agni does.
- **A KiCad board read skips a footprint's undrawn graphics while parsing** (PR 1110). On the Jetson
  seed's board, the geometry layer in the browser engine went from 2265 ms and 412 MB allocated to
  1223 ms and 181 MB, retaining the same 21 MB, and the worker's memory after it from 614 MB to 438 MB.
- **The hierarchy note says when a block placing itself stopped a flattened read** (PR 1109), where
  it used to claim only the top cell was read. Each unexpanded block carries a `reason`.

## Fixed

- **Two blocks' instance-named parts no longer merge in a flattened read** (PR 1109). A netlist with
  no designators names parts by instance name, which is unique only within a cell, so two blocks'
  `R1` read as one part. A name used in more than one cell instance now carries its block's path.

## Docs

- `architecture/ingestion-and-ir.md` states the flattening rules, and the projects guide documents the

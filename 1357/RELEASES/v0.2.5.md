# v0.2.5

A faster Run checks in the browser, and a public-demo walk that reports what loading a design costs
apart from what asking it a question costs. Nothing a gate reads changed.

## Changed

- **The browser engine collects between requests and between a read's files, rather than beside
  them** (PR 1059, agni issue 1010). Go's wasm port runs on one thread, so a concurrent collection
  slowed whatever request was evaluating. On the deployed demo, Jetson's first Run checks went from
  11.5 s to 4.6 s and `profile/spi_nor-signal-missing` from 2059 ms to about 170 ms. Collecting as
  each file of a read opens keeps a worker opening a design at about the size it did before.
- **The viewer's `looks wrong?` link names a finding's severity as a value** (PR 1059), so the
  issue it opens no longer reads "a error".
- **jaala v0.1.69** (PR 1062). Jetson's timings and every seed's findings are unchanged.

## Tooling

- **`make exercise-public-demo` with `--timing` splits a design's load from its questions** (PR 1063,
  agni issue 1060). New rows are `1. load` (the engine's loading during the open), `checks load`
  (the first Run checks' loading, with the time spent outside the engine), `checks rules` (rule
  evaluation alone) and `checks again` (a second Run checks on the loaded design). `make wasm-bench`
  prints its rows in the same two groups and adds `check_load_ms`, `check_rules_ms` and
  `check_again_ms`.
- **`make wasm` can rebuild in the same tree**, since it now installs Go's `wasm_exec.js` writable
  instead of copying the toolchain's read-only file.

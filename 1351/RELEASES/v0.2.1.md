# v0.2.1

A patch release carrying one fix, two new check rules, and one new example.

Note the version number understates this.  Two new built-in rules mean `agni check` reports findings
it did not report in v0.2.0 on unchanged input, which would ordinarily be a minor.  It is tagged as a
patch deliberately, because there are no external consumers yet.  If you gate CI on `agni check`, read
the two rules below before upgrading: a pipeline that was green can go amber on findings that were
always true and simply were not being looked for.

## Fixed

- **The viewer's default layout opened on Trace, hiding the query surface.**  `dock.ts` adds the Trace
  panel `within` the Query group so the two share a tab strip, and dockview makes the last panel added
  the active one.  The block that sets each stack's opening tab covered `details`, `checks`, `review`
  and `canvas` but never `query`, so the stack opened on Trace and contradicted that block's own rule,
  "Each stack opens on its first tab".  A reader loading the viewer got an empty Trace panel and had
  to find the Query tab before they could ask anything.

  Introduced in v0.2.0 by PR 611, which added the trace panel and turned the query panel into a stack
  without adding it to that list.  It shipped because `make browser-test` is not part of
  `make testall`: the textarea was present in the DOM the whole time and only its visibility was
  wrong, which is precisely the class of defect jsdom cannot see.

  The fix carries two gated tests so the browser suite is not the only thing standing between this and
  a release.  One pins the defect; the other is the general rule, that every stack holding more than
  one panel names an opening tab.  Both assert the `setActive` call rather than the pixels, the same
  limit the `resizeGroup` comment above them already records.  (PR 620)

## Added

- **`i2c-redundant-pull-up`** reports an I2C net that reaches one rail through more than one resistor.
  It counts distinct resistors taking the net to a rail within three series crossings, so two routes
  through one resistor stay one pull-up.  Resistors in parallel are one smaller resistor, so two 2.2k
  pull-ups are an effective 1.1k and the bus sinks roughly twice the current it was sized for.  An
  open-drain device can only pull the line low by sinking that current, so an over-pulled bus works
  with some parts and not others, or idles with a low level high enough to read as neither state.  It
  arrives the same way nearly every time: a module carries its own termination so it works standalone,
  the board it plugs into already pulls the same bus, and neither schematic is wrong on its own.
  (PR 619)

- **`i2c-pull-up-split-rail`** reports an I2C net that reaches two different rails through its
  pull-ups.  That ties the two rails together through the bus, so whenever one supply is up and the
  other is not, current flows from the live rail through its pull-up, along the bus, and back into a
  rail meant to be off.  It can hold a supply above its off threshold, back-feed a regulator, or bring
  a device up in a state its reset never sees.  The bus also idles at whichever rail wins, which may
  exceed the input rating of a device on the lower supply.  (PR 619)

- **`examples/dft-coverage`**, an example that measures design-for-test coverage over a board.
  (PR 618)

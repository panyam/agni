# v0.3.13

v0.3.13 makes the CLI installable in one step. Each release now attaches a prebuilt `agni` for macOS
and Linux on arm64 and amd64 that carries the browser viewer, and a `go install` build fetches the
viewer from its release the first time it needs one, so `agni open` works outside a checkout either
way. It also fixes `agni open` on a board with no project above it, which since v0.3.0 landed on a
page asking for the browser engine instead of the viewer. Everything is additive.

## Added

- **Release binaries** (PR 1226). Each release attaches `agni_<tag>_<os>_<arch>.tar.gz` for
  darwin and linux on arm64 and amd64, each holding an `agni` built with the viewer embedded, plus
  the viewer alone as `agni-web-<tag>.tar.gz` and a `checksums.txt` covering every file. The release
  workflow's `binaries` job builds them with `make dist V=<tag>`, runs one from an empty directory
  (`hack/dist_smoke.sh`: version, a check on the demo board, and `open` serving the page and its
  bundle), and attaches them.
- **A viewer for `go install`** (PR 1226). A build installed with `go install` carries no viewer,
  since the built JavaScript is not part of the Go module. When nothing names a web dir and there is
  no `./web`, `agni open` and `agni serve` now download the bundle the binary's own release attached,
  check it against that release's `checksums.txt`, and keep it in the user cache directory, so later
  runs work offline. A release binary writes its embedded copy there instead. A build that is not a
  release tag (`make agni`, `@main`) has neither, so `serve` still runs the API alone and `open` now
  says where a build with a viewer comes from.

  ```
  go install github.com/panyam/agni/cmd/agni@v0.3.13
  agni open board.kicad_sch
  ```

## Changed

- **The README and the docsite home lead with what agni catches** (PR 1205): a bus with no pull-up,
  a rail with no decoupling, a connector with no ESD protection, with the browser demo linked first.
  The quick start installs with `go install`, a release tarball or a `docker run` line, and fetches
  the demo board with `curl` rather than a clone. Every docsite page and the demo landing page carry
  `og:*` and `twitter:card` tags, so a shared link shows a card; `agni site --social-image <url>` sets
  the demo's image.
- **A file with no project above it is minted the mount `files`** (PR 1226), where it was `local`.
  This shows in `mount://` URIs and in the `--server` notes of a run over a loose file.

## Fixed

- **`agni open` on a loose board reaches the viewer** (PR 1226). The minted mount was named `local`,
  which the viewer keeps for files dropped on a page, so the Load page took the board for a drop and
  refused it on the server engine with "this page needs the browser engine". The name `local` is no
  longer handed to any minted mount.

## Releasing

`RELEASING.md` step 6 attaches the compose bundle with `hack/release_attach.sh` and publishes with
`gh release edit --draft=false`, since the `binaries` job may create the release as a draft first.

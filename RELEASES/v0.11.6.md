# v0.11.6

A person with a local account could sign in at `/signin` in a browser, but a terminal had no way in. They had to ask the operator for `agni token create`. The compose bundle and the Helm chart also had no switch for local accounts. v0.11.6 adds `agni login --with local`, and turns local accounts on in the bundle and the chart. It is a patch over v0.11.5. No exported Go API and no proto field changes shape.

## Added

- **`agni login --remote <url> --with local --user <name> --password-stdin` signs in from a terminal with a local account** (PR 1886, issue 1879). It keeps the token the same way the GitHub and OIDC logins keep theirs. `POST /signin/local` also takes a JSON body and answers `{token, subject, expires}` with no cookie. A refusal answers `{error}` with a 401, a 429 or a 400. The JSON path goes through the same rate limits and the same password check as the form.
- **The enterprise compose bundle and the Helm chart turn local accounts on** (PR 1886). The bundle reads `AGNI_LOCAL_ACCOUNTS`, and the chart reads `localAccounts`. Both default to off. The deploy guide shows how to add an account in each, through `docker compose exec` or `kubectl exec`.

## Changed

- **The enterprise exercise signs a local account in from the form and from the CLI in every mode** (PR 1886): binary, compose bundle and Helm on kind.
- **A browser test drives the local sign-in form into the viewer** (PR 1886). A second test confirms that a local user can add, list and use their own GitHub connection with `agni connections add --mine`.
- **`agni login`'s errors mention local.** A server with no device-flow provider points to `agni login --with local`, and a bad `--with` says "want github, oidc or local".

## Not in this release

Password reset by email waits on issue 1884. `agni users passwd` resets a password today.

# v0.3.10

v0.3.10 puts a reader's question from a viewer tab in front of a Claude Code session as a turn of
its own, rather than waiting for an agent to poll for it. It also lets a Review finding open onto
the facts that make it hold, and makes the MCP server's two wires behave the same. Every change is
additive, and the rooms are still off unless `agni serve` is started with `--viewer-rooms`.

## Added

- **A tab's question reaches an agent as an event** (PR 1187, issue 1173). Under
  `agni serve --mcp --viewer-rooms` the room bridge also serves a tab's page events as SEP-3415
  events (`room.ask`, `page.selection_changed`, `page.event`) through mcpkit's `roomsevents`. A
  session attached to a design's room hears each question from a tab that let agents in, and none
  from a tab that didn't. mcpkit's `rooms-channel` turns those events into Claude Code channel
  messages, and `guide/asking-with-an-llm.md` says how to set it up. The events need the session
  wire. `next_request` keeps working beside them on both wires.
- **A tab says when the bridge refused one of its tools** (PR 1187). A note beside the agents switch
  names the tool, with the bridge's reason in its tooltip. That only happens when the page and the
  server come from different builds.
- **A Review finding opens onto how it holds** (PR 1185). A finding of a checklist item backed by an
  inline query gets an arrow. Opening it asks the item's query again for that subject with witnesses
  on and draws the tree the query panel draws, and each net, part and pin in it locates on the sheet.
  The query is read off the run's stored manifest, so a saved run asks the question it scored.
- **The MCP `query` text carries each row's witness tree** (PR 1185), in the shape
  `agni query --witnesses` prints, so an agent reading the text sees it too.
- **`intent/pull-up-reach-declared`** (PR 1182) gives one verdict per net a design declares a
  `pull_up_reach_hops` for, and fails a name the design lacks, where a misspelled net used to change
  nothing.

## Changed

- **The I2C pull-up count rules show every path** (PR 1182). `i2c-redundant-pull-up` and
  `i2c-pull-up-split-rail` build their evidence as `i2c-pull-up` does, so a pull-up behind a series
  resistor keeps its middle hop, and each of several pull-ups gets its own path. Paths sort in
  natural order, R2 before R10.
- **The MCP lists hold for an hour** (PR 1184). The tool, resource and prompt lists carry
  `ttlMs: 3600000` on both wires, so a stateless client stops fetching `tools/list` again in every
  conversation.
- **The review tour's last two step shapes** (PR 1181). "Click into an answer" advances only on a
  part and ends the tour on any other cell, and "Ask a follow-up" offers both the Query panel's Ask
  button and the Ask rows in Properties.

## Fixed

- **The stateless MCP wire behaves as the session wire does** (PRs 1181, 1187). agni now sets the
  wires it accepts rather than taking mcpkit's default, and with mcpkit 0.8.13 the stateless wire
  refuses a misspelled tool argument, `agni mcp` on stdio serves a stateless client, and an adaptive
  client falls back from a session-only server. `examples/ask-over-mcp` speaks adaptive over stdio
  too.
- **`make proto-check` no longer reads red under a newer local Go** (PR 1186). `proto` and
  `proto-check` run generation under the Go `go.mod` names.

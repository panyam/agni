# v0.3.12

v0.3.12 makes two things installable without a checkout. A team whose microcontroller pin-mux table
already lives in a spreadsheet can now get it into the datasheet corpus, so the pin map's function
checks read it instead of reporting every declared function as not considered. And the Python client
is published to PyPI with each release, so calling agni from Python no longer starts with cloning
this repository. Everything is additive.

## Added

- **`agnids merge-mux <mux.yaml> --corpus <dir>`** (PR 1201, issue 1200) merges a pin-mux table kept
  as its own file into the spec the corpus publishes for that part. The file is a part spec in YAML
  holding only pins and their `alternates`, with the same field names a published spec uses, so a
  team writes it from the spreadsheet it keeps and the format in `guide/datasheets.md` is that
  converter's contract. Each table pin joins the published pin it describes by id, then by a
  designator the two share, then by name, and an ambiguous match such as a repeated `NC` is refused
  rather than guessed. A joined pin adds the table's alternates to its own, skipping a name it already
  lists, so a part split across two tables merges from each and a repeated merge changes nothing.
  `--replace` takes the table's alternates in place of the pin's own, which is how a revised table
  drops a function. The merged spec is validated and written back to the file that already seeds the
  part, with the corpus index updated, so the corpus still holds one file per part. The datasheet
  layer page now separates the three records about a pin: the board's allocation (`io_map`), the
  part's mux table (`Pin.alternates`) and its parameters.
- **The Python client on PyPI as `agni-eda`** (PR 1204). The release workflow builds the client at the
  tag's version, installs the wheel into a fresh venv outside the checkout to check it, and publishes
  it through PyPI trusted publishing. The import stays `agni`; the distribution name differs because
  PyPI's `agni` is an unrelated project. `make python-dist V=vX.Y.Z` runs the same build and check
  locally, and the gate runs it as `python-dist-check`. `build/other-languages.md` gives the PyPI and
  git-ref install lines.

  ```
  pip install agni-eda
  ```

## Changed

- **`core/param` gains `CheckPinMux`, `MergePinMux` and `PinMuxMerge`** (PR 1201), the pure merge the
  command runs, so another host can merge a table without the datasheet service. The YAML reading is
  `corpus.LoadPinMux` in the datasheet module, which keeps `core/param`'s dependencies to protobuf
  and `core/ident`.

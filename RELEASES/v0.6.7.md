# v0.6.7

v0.6.7 carries one PR. A sheet view shows a loader of its own while it draws. WebGL frames each
placement of a ref-des on its own. The release is a patch, with no Go API change. One wire message
gains a field.

## Added

- **A sheet view shows its own loader while it draws** (PR 1478). A large board takes a second or
  more to draw beside the schematic, and the view stayed blank or frozen meanwhile. The view now
  covers its own stage with a loader, so the canvas and the other views stay usable. It shows when
  the view opens, picks another sheet, follows a selection to another sheet or switches renderer.
  A draw under 120 ms shows nothing. A drawing over 1 MB puts the loader up at once, since putting
  it on screen blocks the page before the show delay can run out. On Jetson's board the loader
  appeared before the page blocked on both the server and the browser engine, where before it
  never showed on the server.

## Fixed

- **WebGL frames each placement of a ref-des on its own** (PR 1478, issue 1477). A sheet that
  places R2 twice lit each placement in SVG. WebGL drew one frame from the first to the second,
  covering everything between them. A listed pin had the same problem. Each placement now frames
  where it sits, and the part is still named once in what is lit.

## Wire

- `PrimitiveKey` gains `placement`, the 1-based index of the symbol placement that drew a symbol,
  pin or DNP primitive (PR 1478). It is 0 on a board and on every other primitive. A client that
  ignores it draws as before, with one frame per ref-des.

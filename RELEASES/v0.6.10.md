# v0.6.10

v0.6.10 continues the board-open mission (issue 1499). Both reload targets now pass. On Jetson's
board, measured headed on an M5 Pro at `a8cda0fe`, a server reload draws in 306 ms and a reload in
the in-browser engine in 377 ms, against 302 ms and 491 ms in v0.6.9. The browser-engine reload
gains the most, because a packed sheet's keys and labels now travel as columns, and the canvas
paints copper before it lays out text. A selected part also gets an opaque outline. It is a patch.
The packed sheet's wire form changed, and the Changed section says how a Go reader of that form
moves over.

## Changed

- **A packed sheet sends its keys and labels as columns** (PR 1538, issue 1532). Each column
  message holds one string table and fixed-width records. On Jetson the page decodes them in about
  1 ms, where 37,320 key messages and 5,732 label messages took about 35 ms. The generated
  `geom.PackedSheet` no longer has `Keys` or `Labels`. Go code reads them with `render.PackedKeys`
  and `render.PackedLabels`. The packed layout version is now 2, so a board cached by an older build
  is packed again once, and a browser-engine seed from an older server misses once.
- **The canvas paints a sheet's geometry before it fills the text layer** (PR 1533, issue 1503).
  The 5,732 labels on Jetson's board fill on the frame after the first draw. With `?timing` set,
  the canvas logs one `agni sheet` line per draw.
- **A selected part frames with an opaque outline over its translucent fill** (PR 1537, issue
  1536), in SVG and in WebGL, on a sheet and on the board. A small part's frame is at least 1.5% of
  the drawing's smaller span, so a two-pad footprint frames at about twice its old span. The
  Highlight menu's width slider scales the outline. On the board in SVG, a selected part now gets a
  frame, where it used to get only a ring per pad.
- **A board view with no renderer named opens in WebGL when the canvas does or the GPU is
  hardware** (PR 1537). A schematic view still opens in the canvas's renderer.

## Tools

- **`tools/coldparse` times a fresh server's first board parse** (PR 1535, issue 1531). The
  exercise's server cold row splits into two clusters. On Apple Silicon the same parse runs about 6
  to 10 times slower in about half of fresh servers, most likely on an efficiency core. Issue 1534
  holds the options for a fix, and `web/browser/CLAUDE.md` says to read server cold by its fast
  cluster.

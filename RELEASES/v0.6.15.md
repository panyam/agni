# v0.6.15

v0.6.15 makes `agni serve` on macOS answer a cold parse quickly every time. macOS used to run some request threads on its efficiency cores, so about half the cold parses of the Jetson board came back slow. It also splits the browser suite into ten CI shards. It is a patch. No API changes.

## Changed

- **`agni serve` on macOS raises each request's thread to user-initiated QoS** (PR 1570, issue 1534). Go's threads start at the default class, and macOS scheduled some of them on efficiency cores while a parse ran. On an M-series laptop, 27 of 60 cold parses of the Jetson board came back fast before the change, and 60 of 60 after it, with a median of about 154 ms. A thread already at a higher class keeps it. Other platforms are unchanged. Issue 1569 holds the Windows counterpart, EcoQoS on hybrid CPUs. The binary now depends on `github.com/ebitengine/purego` v0.8.4 to call the pthread QoS functions without cgo.

## Build and CI

- **The browser suite runs as ten CI shards instead of four** (PR 1571), so the gate's slowest job is shorter.
- **The Trace tab's end-pin test waits for the reachability answer** (PR 1568). It read the end pin's detail before the answer arrived and failed now and then on CI.
- **RELEASING.md says to tag only once the notes commit is `main`'s tip.**

# v0.3.11

v0.3.11 lets a reviewer sign off a board's pin map in one place. A design intent's IO map is laid
out one row per declared pin, beside the net the netlist puts there and the functions the part's
datasheet lists for that pin. That page can also carry the project's query sets, and `agni trial`
reports the map as counts a team can send back from a board we never see. Everything is additive
for a Go caller. A TypeScript or Python client importing `OverlayConfig` changes one import line
(Changed, below).

## Added

- **The pin map** (PR 1192, issues 1188 and 1189). `check --format html` opens with a "Pins on
  <device>" section for each device an IO map names, one row per declared pin. Each row shows its
  function, declared net, the net the netlist puts there, the far end with its route, and what each
  IO-map check concluded. The same rows are the `pin_map` table `Tabulate` returns for a check run.
  `check --verdicts --format json` carries the map the run checked (`ioMap`), so the rows join
  without a model.
- **A declared function is checked against the datasheet** (PR 1195, issue 667). The parameter
  contract gains `Pin.alternates`, the functions a pin can be muxed to. A third recipe table kind,
  `MuxTableRule`, reads them from a vendor's pin-mux table, in NXP's one-row-per-pin layout and TI's
  one-row-per-function layout. `intent/io-map-function` fails a function the pin doesn't offer and
  lists the ones it does. A part with no datasheet entry, or no pin-mux table, reads as not
  considered, with the reason.
- **`check --verdicts --format csv --table <name>`** (PR 1195) writes one of the run's tables
  instead of the verdicts: `pin_map`, `verdicts_by_rule` or `skipped`.
- **`make exercise-pin-functions`** (PR 1195) runs mission 1194's exercise, the HTML report and the
  `pin_map` csv for `PIN_DESIGN`.
- **`check --format html --query-sets`** (PR 1199, issue 1190) answers every query set the design's
  project keeps and adds each as a Queries section after the rules, so one file carries the checks
  and the queries. Without the flag the page is unchanged.
- **`agni trial` counts the pin map** (PR 1198, issue 1196). It reports the map's rows, what each
  check concluded, why each declared function went unchecked (as a fixed kind), and how many matches
  were inferred. No pin, net or function is kept. `guide/trying-agni.md` describes signing off a pin
  map in a clean room.

## Changed

- **`trace` takes a pin's functional name** (PR 1197, issue 1193). `--from U2.MDIO` resolves through
  `check.LookupPin`, the lookup the IO-map rules use. A name several pins carry, or one a pin
  matches only loosely, is refused with the candidates. A designator resolves as before.
- **The IO-map rules state a failed pin lookup as their witness** (PR 1192), as the verdict contract
  says, rather than as a reason. Rows that declare a function no longer carry a "NOT evaluated"
  note, since `intent/io-map-function` now decides them (PR 1195).
- **`OverlayConfig` moved to `webapi/config.proto`** (PR 1199), beside the `AnalysisConfig` it wraps,
  so the check report request can carry query results without an import cycle. Go code is
  unchanged.
  - TypeScript: import it from `agni/v1/webapi/config_pb` rather than `checks_pb`.
  - Python: import it from `agni.v1.webapi.config_pb2` rather than `checks_pb2`.

## Fixed

- **An EDIF part whose ports state their pin numbers only on the cell** (PR 1197, issue 1193). A net
  now lands on the numbered pin. Before, it connected to a pin named after the port, which the part
  type didn't have, so the part's pins sat on no net. A port is mapped through the instance's
  `portInstance` first, then the cell port's own `designator`.
- **The verdict csv's `context` column names a pin with its pin** (PR 1197): `declared pin=U1.PTB3`
  where it used to print `declared pin=U1`.

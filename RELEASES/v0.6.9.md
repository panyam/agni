# v0.6.9

v0.6.9 carries most of the board-open mission (issue 1499): a board opens faster in the browser,
against a server and in the in-browser engine alike. On Jetson's board, measured headed on an M5 Pro
at `fc4b6481`, a server reload draws in 302 ms where v0.6.8 took about 600 ms. A reload in the
in-browser engine draws in 491 ms, against about 2.1 s, and a first visit there draws in 1.9 s,
against about 6.0 s. A page now opens in WebGL on a hardware GPU. The release also adds a checklist
answer taken from another tool's report, finishes the rule and profile card diagrams, and splits the
CI gate into parallel jobs. It is a patch, with no change to an existing Go API.

## Added

- **`make exercise-board-open` times Jetson's board to its first WebGL draw** (PR 1508, issue 1500).
  It opens the board five ways (a fresh server, a reload, a new browser on a warm server, and the
  browser engine cold and reloaded), judges each median against the mission's targets, and names the
  requests that held the page. Each row also counts the design files' bytes over the network (PR
  1516) and lays out every page's startup (PR 1526).
- **A page opened with `?timing` logs its startup** (PR 1526, issue 1524). One `agni boot` line per
  page says when its script ran, when each browser-engine worker had loaded `agni.wasm`, and when the
  engine was ready.
- **`agni serve` answers `/seed/<mount>/<path>`** (PR 1530, issue 1525) with a design's store as a
  browser worker would write it, built by the engine's own code. The Load page puts it into the
  worker's store on a first visit, so the worker restores the parsed board instead of fetching and
  parsing it. A worker takes a seed only under its own store version. On Jetson the seed is about
  14 MB, against an 85 MB board file.
- **A checklist item can take its answer from another tool's imported report** (PR 1496, issue
  152).

## Changed

- **A page opens in WebGL on a hardware GPU, and in SVG otherwise** (PR 1505, issue 1329). The page
  reads the WebGL2 renderer name. A software renderer such as SwiftShader or llvmpipe opens the page
  in SVG, as does a browser without WebGL2. An address's `?mode=` still decides when present.
- **A design opened on its board draws the board before anything else** (PR 1511, issue 1501). The
  Load page skips reading the schematic, and the viewer asks for the sheet list, the project and the
  Properties inventory only after the board is on screen.
- **The viewer speaks binary Connect** (PR 1516, issue 1502). A packed board is mostly an int32
  blob, which JSON sent as base64. The browser engine's fetch, the dropped-design refusal and the
  static site's workspace read either codec.
- **The packed Board sheet is kept in the design cache** (PR 1523, issue 1522), on the server in
  memory and in the browser engine's store, so a board view restores it instead of packing the board
  again.
- **A browser worker checks a stored read by the page's listed hashes** (PR 1520, issue 1515). A
  worker holding the board only as a placeholder restores it from the store, without fetching its
  bytes. The store's fingerprint format changed, so a store written by an older build is read again
  once.
- **A page lists each design once** (PR 1528, issue 1527), for the Load page's record and the
  browser engine's file bring alike.
- **`/raw/` asks the browser to revalidate a design file** (PR 1516) with `Cache-Control: no-cache`.
- **The sheet views close when another design opens**, and a KiCad wire keeps its net's id (PR
  1489, issue 1425).
- **`make agni` and `make install` stamp the same build id as `make wasm`** (PR 1530), so a dev
  server and its page agree on the store version.

# v0.11.9

v0.11.8 let an operator grant a private source to people who sign in, on `agni serve` alone and by subject pattern. A person a grant admitted was still refused the same mount on the datasheet workbench, the compose bundle had no way to set a grant, and a grant couldn't follow a group. v0.11.9 closes all three. It is a patch over v0.11.8. No proto field changes, and the one exported Go change adds a field to `service.Caller`.

## Added

- **`agnids` reads grants, and both servers take `--grants-file`** (PR 1898, issue 1895). `--grants-file` names a YAML file holding only an `access` list in serve.yaml's shape, and an empty list grants nothing. `agnids` also takes `--grant`.
  - Give agnids the grants agni serve has, or a person opens a mount on the viewer and is refused it on the workbench.
  - On agnids a grant needs `--auth tokens` and `--connections-key`, since agnids checks a caller only through agni serve's connections.
  - On agni serve, `--grants-file` is refused beside `--grant` or a serve.yaml `access` list.
- **The enterprise bundle keeps its grants in `access.yaml`** (PR 1898). The release tarball ships the file granting nothing. Both `agni` and `datasheets` mount it read-only and pass `--grants-file`. `AGNI_ACCESS_FILE` in `.env` names another file. Restart both after an edit. `make exercise-enterprise-bundle` now runs the grant step that v0.11.8 skipped.
- **A grant can name an OIDC group or a GitHub org** (PR 1899, issue 1896). `oidc:group:<id>` admits a person whose OIDC sign-in listed `<id>` in the groups claim. `github:org:<org>` admits a person who was a member of `<org>` when they signed in with GitHub.
  - The sign-in records these claims on the person's token, and every check reads them from there with no call to the identity provider or GitHub. agnids reads the same tokens.
  - A change reaches a person at their next sign-in. Someone added to a group, or a server restarted with a new `github:org:` grant, signs in again to get it. Someone removed from a group keeps the grant until their token expires or `agni token revoke` revokes it.
  - A token from `agni token create` carries no claims, so a claim pattern never admits one.
  - GitHub sign-in asks about each org a `github:org:` grant names, through the App, which needs the Members organization permission at Read there. It asks about no other org, so a person `--github-allow` names as `user:` still needs no org check. `github:org:*` names no org and admits nobody.
  - An identity provider that leaves the groups claim out, as Entra does past 200 groups, gives the person no groups.

## Changed

- **agni is on goapplib v0.7.39**, which adds `connections.WithViewerClaims`.
- **`service.Caller` has a `Claims` field**, which the auth gate fills from the request's token.

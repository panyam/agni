# v0.11.8

A team server under `--auth tokens` opened a design linked from a private repo only for a caller whose own GitHub connection reads that repo. A person signed in with a local account or through OIDC holds no such connection, so they saw nothing. v0.11.8 lets the operator grant a private source to people by subject. It is a patch over v0.11.7. No exported Go API and no proto field changes shape.

## Added

- **`agni serve --grant source=pattern,pattern` opens a private source to the people it names** (PR 1897, issue 1889). The flag repeats. `serve.yaml` takes the same as an `access` list of `{source, allow}`, and a typed `--grant` wins over the file. A pattern is `*` for anyone signed in, `local:*`, `oidc:*` or `github:*` for anyone of that kind, or one subject such as `local:carol`.
  - A matching caller reads the source's designs, files and mount with no call to GitHub. Anyone else falls through to their own connection, as before.
  - The server checks each grant at startup, and a bad one stops it with an error naming the entry.
  - `--grant` without `--auth tokens` is refused, since without `--auth` every caller reads everything already.
  - The source matches byte for byte, so copy it from `agni mounts ls`.
  - `*` admits every token from `agni token create`, scripts and CI included.
  - The deploying and running-the-server guides cover it, and `make exercise-enterprise` runs a grant step.

## Changed

- **agni is on goapplib v0.7.38**, which adds `connections.WithSourceGrants`.

## Not in this release

The compose bundle passes no `--grant`, and the datasheet workbench `agnids` builds its table with no grants, so a granted person is refused a mount there (issue 1895). Claim patterns such as `oidc:group:<id>` and `github:org:<org>` wait on issue 1896.

# v0.11.0

A team can now run agni inside its own network, against its own GitHub Enterprise Server. Each release ships a compose bundle (PR 1832) and a Helm chart (PR 1837). Both serve agni with TLS or behind an ingress, take every secret from a file or a Secret, and sign people in through a GitHub App or the company's OpenID Connect provider (PR 1842). A new guide walks an admin through it, at `guide/deploying/` (PR 1843). The release runs the enterprise exercise against both, over the published image, before it publishes them. The server's records can also live in sqlite, postgres or Cloud Datastore (PRs 1822 and 1825). Uploads can live in an S3 or Cloud Storage bucket (PR 1834), and a design can link from an S3, Cloud Storage or SharePoint folder (PR 1831). A pack can follow a branch of a repo (PR 1819), and a checklist can be a folder of item files (PRs 1835 and 1839).

It is a minor release over v0.10.0. Four exported Go interfaces and methods in `service` and `mountset` change shape, so read the Breaking section if you embed agni. No proto field changes shape.

## Breaking

- **`service.UserTokenKeeper` gains `SaveServerSecret(ctx, id, secret string) error`** (PR 1832). The connection service seals a server connection's secret through it. Migration: add the method to your implementation, or embed agni's.
- **`service.ProjectRecords` gains `Create` and `Update`** (PR 1825). `Update(ctx, id, func(*webapi.Project) error)` changes a record only if nobody wrote it in between, so two servers can share a store. Migration: implement both. `Create` of a taken id is `ErrAlreadyExists`, and `Update` runs the function again on the newer record when another writer got there first.
- **Webhook secrets are a `service.WebhookSecrets` instead of `[]byte`** (PR 1831). This changes `service.WebhookMaker.CreateWebhook`, `mountset.Table.CreateWebhook` and `service.WorkspaceService.WithWebhooks`. The struct carries the GitHub secret and the Graph `clientState`. Migration: pass `service.WebhookSecrets{GitHub: secret}`.
- **`mountset.Table.Blobs()` returns a `blobs.Linker` instead of a `*blobs.Dir`** (PR 1834), since uploads can now sit in a bucket behind a local cache. Migration: call the `blobs.Linker` methods, which `*blobs.Dir` still implements.

## Added

### Running inside an enterprise

- **A deployment bundle for a team's own GitHub or GitHub Enterprise Server** (PR 1832, issue 1802). Each release attaches `agni-enterprise-<version>.tar.gz`, a compose file and an env example. They run `agni serve` with TLS, `--auth tokens`, sign-in through a GitHub App, a connections key and webhooks, and agnids beside it on a profile. Every secret comes from a file the env names. `--github-api` is now a documented flag on both servers, and `agni healthcheck --tls` probes a server that ends TLS itself.
- **A Helm chart for agni and agnids** (PR 1837, issue 1803). Each release publishes it to `oci://ghcr.io/panyam/charts/agni` at its version. It serves agni behind the cluster's ingress with `--trusted-proxy`. Every secret comes from a Secret the team makes, and the store and uploads sit on a claim, in postgres or in a bucket.
- **Sign in through an OpenID Connect provider** (PR 1842, issue 1811), such as Entra ID, Okta or Google Workspace, beside GitHub or instead of it. A browser signs in at `/signin/oidc`, and `agni login --with oidc` uses the provider's device flow. `--oidc-allow` takes `domain:`, `group:`, `sub:` and `hd:` entries, and the person becomes the caller `oidc:<sub>`. The bundle and the chart pass the flags when an issuer is set.
- **`--trusted-proxy` serves `--auth tokens` behind a proxy that ends TLS** (PRs 1821 and 1829, issue 1810), such as a Kubernetes ingress or a cloud load balancer. The server then serves plain HTTP on any address, and a request the proxy took over HTTPS gets Secure cookies. X-Forwarded-Proto from any other peer is ignored. agni reads the header through servicekit's `TrustedProxies`.
- **A server connection can keep its secret sealed** (PR 1832). `agni connections add --seal` reads a token, or a GitHub App's key, where the CLI runs. The server seals it under `--connections-key`, so a server in a container needs no reference into its own environment. `agni connections rotate` replaces it while mounts keep reading through the connection.
- **The CLI trusts a team's own CA from `AGNI_CA_FILE`** (PR 1814, issue 1800), for every `--remote` call and for `agni login`.
- **The guide `guide/deploying/`** (PR 1843, issue 1804) takes an admin from a fresh machine or cluster to a running agni. It covers registering the App, the secrets, the bundle or the chart, sign-in, linking a design and a pack, who can open it, what leaves the network, upgrades and backups. A test checks that every env line and chart value it names still exists.

### Stores and buckets

- **`--store` takes `sqlite://`, `postgres://` and `datastore://`** beside `file://` (PR 1822, issue 1733). Every record moves, including runtime mounts, connections, sealed tokens and the `--auth` tokens. `agni token --store` and `agnids serve --store` take the same URL. A `file://` store keeps the layout it always had.
- **Two servers can share one store** (PR 1825, issue 1823). Every read-modify-write of a design, pack or project writes only if the record is unchanged since the read, and the losing writer tries again. `agni serve` sweeps a Datastore write's stranded parts every hour.
- **`--uploads s3://` and `gs://`** keep every uploaded and snapshotted file in a bucket (PR 1834, issue 1730). `--uploads-cache` names the local folder for copies and views. A server that starts with an empty folder, such as a pod on a fresh node, rebuilds every view from the bucket.
- **A design links from an S3, Cloud Storage or SharePoint folder** (PR 1831, issue 1729). `CreateMount` takes `s3://`, `gs://` and `msgraph://` URIs, and connections gain AWS, GCP and Entra credentials. A SharePoint mount follows its drive through Graph's change notifications, with `--msgraph-client-state` and `agni mounts webhook`. `--s3-endpoint`, `--gcs-endpoint` and `--graph-api` reach MinIO, a national cloud or a fake.

### Packs and checklists

- **A pack reads from a project folder in a repo and follows its branch** (PR 1819, issue 1801). `agni packs link house rules@main` links one. A push webhook, `--poll` or `agni packs sync` moves it to the branch's new commit, so the next check runs the new rules. Each report names the commit its packs were read at, and a pack from a private repo opens only for who can read the repo.
- **A checklist can be a folder of item files** (PRs 1835 and 1839, issue 1812). A checklist in `project.yaml`, `design.yaml` or a standalone manifest names `items_dir:`, and each `.md` file under it is one item. `--checklist checklist/` takes the folder itself. `agni packs push` and linked packs carry the item files. `agni checklists packs/<id> --remote` lists a pack's checklists.

## Changed

- **Dependencies.** goapplib v0.7.34, oneauth v0.3.21, servicekit v0.2.5 and panyam/ci-actions v0.1.5, in every module (PRs 1817, 1824, 1829, 1834, 1835, 1837 and 1844). goapplib's mount drivers take a typed credential, and agni passes the connection service's `Credentials`.
- **A private GitHub mount asks GitHub only through a viewer's GitHub connections** (PR 1837), so a viewer's connection of another kind never reaches api.github.com.
- **A GitHub mount reads Git LFS objects** (PRs 1817 and 1818). A `github://` mount swaps an LFS pointer for its object, including an object smaller than its pointer or in a repo with no `.gitattributes`.
- **An `--addr` with no port, such as `localhost`, gets a parse error naming `--addr`** (PR 1829). Before, it got the "in the clear" refusal.
- **A GitHub sign-in callback with a bad state answers 400** (PR 1832).
- **The example projects keep their boards under `boards/`** instead of `designs/` (PR 1840, issue 1838), so a folder path no longer reads like a server's `designs/<id>`. A checkout that copied the Jetson boards before reruns `make -C examples/jetson-project board revision rev-b`. Server resource names stay as they were.

## Fixed

- **A Git LFS pointer agni can't resolve fails with FAILED_PRECONDITION naming the file** (PR 1818, issue 1809). Before, a missing LFS object answered NOT_FOUND as if the mount were gone.
- **A sign-in refused because the GitHub App lacks the Members permission says so** (PR 1844, issue 1841). GitHub answers 403 to the server's org membership check without that permission. The refusal used to read "GitHub answered 403", and now names the permission to add.
- **`agni token list` no longer fails while the server sweeps expired tokens** (PR 1813). It skips a token deleted between listing and reading.
- **The folder store retries a rename or remove on windows** that another handle blocks (PR 1830).

## CI and the gate

- `make exercise-enterprise` runs agni the way an IT admin would, against goapplib's fake GitHub Enterprise Server with TLS, tokens, App sign-in, LFS, webhooks and a trap for any other host (PRs 1814 and 1844). It also runs against the bundle (`make exercise-enterprise-bundle`) and the chart on kind (`make kind-up exercise-enterprise-helm`). CI runs all three, and the release runs the bundle and chart modes over the published image.
- Tests that passed only in file order now make the state they need (PR 1813), and a viewer-room browser test waits for its relay events (PR 1807).
- Every language's generated code is current again after a proto change that regenerated only Go (PR 1833).

# v0.11.1

v0.11.0's tag built the agni image but failed before it published the rest. In the agnids image, agnids exited at start, since it tried to create its `--store` folder `/var/lib/agni/meta` as a user that can't write there. The release's Helm check also never started, since kind couldn't load the multi-platform agni image. So `ghcr.io/panyam/agnids:v0.11.0` never got its tag, the chart never published, and the v0.11.0 GitHub Release stayed a draft. v0.11.1 fixes both. It is a patch over v0.11.0, with no change to an existing Go API. Coming from v0.10.x, read [v0.11.0's notes](v0.11.0.md) first, since its Breaking section applies.

## Fixed

- **agnids starts over a store folder it can't create** (PR 1848, issue 1847). agnids only reads agni serve's `--store`, so it no longer makes the folder, and a folder that isn't there yet reads as empty until agni serve makes it. `storeurl.ReadOnly()` opens a file:// store that way. The agnids image starts again, and `hack/image_smoke.sh agnids` passes.

## CI and the release

- **The release's kind cluster pulls the published agni image from GHCR** (PR 1848) instead of loading a multi-platform image it can't import.
- **images-agnids also runs on changes under `internal/`, `mountset/` and `service/`** (PR 1848). It had failed on every push since PR 1822, and nobody watched it.
- **CI's scan job reads the whole history, as `make secrets` does on a laptop** (PR 1849, issue 1846). `.gitleaks.toml` allows the wire fixture's old page tokens, which history still holds.

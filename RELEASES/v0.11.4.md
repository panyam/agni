# v0.11.4

A team that keeps its `project.yaml` at the top of the folder holding its boards couldn't link that folder as a pack. The link listed every file under the folder, and the boards pushed it past the mount's 256 MB limit, so a bootstrap `packs:` entry kept `/readyz` at 503. v0.11.4 makes a link read what `agni packs push` reads. It also takes `gorilla/websocket` to the commit that fixes GO-2026-6278, through servicekit v0.2.6. It is a patch over v0.11.3. One exported Go type changes shape, `service.PackImporter`, and no proto changes.

## Fixed

- **A linked pack lists only what its `project.yaml` names** (PR 1872, issue 1871). A link lists `project.yaml`, then each path its tiers name, and fetches a file only when the pack reads or keeps it. Boards beside it are never listed or fetched, so they count against no size limit. A link may name `<folder>/project.yaml` as well as the folder.
- **A sync after a commit that changes none of a pack's files leaves the pack unchanged** (PR 1872). A board edited beside a linked pack used to rewrite it on the next push webhook or poll. The pack now records the new commit and reports unchanged.
- **GO-2026-6278 is fixed** (PR 1872, issue 1868). servicekit v0.2.6 moves `gorilla/websocket` to `v1.5.4-0.20240701034025-d67f41855da4`, where a client's mask keys come from `crypto/rand`. No tagged gorilla release has the fix yet.

## Changed

- **`service.PackImporter` takes a lister in place of the folder's paths** (PR 1872). An embedder passing its own importer to `PackService.WithImporter` switches to `projects.PackFromFolder`. `projects.ListFiles` turns a list of paths into the lister it takes.

## Upgrading

A pack linked before v0.11.4 recorded a read hash over its whole folder. Its first sync after the upgrade reads it as changed and rewrites it once, with the same files.

# v0.8.0

v0.8.0 carries most of mission 1664, so a board opens in 3D the way its maker's tool shows it. Each part stands on the board at its real height and outline, KiCad's from the part's STEP model, and Altium's, Allegro's and ODB++'s from the file. The stack view gains a Board look, cut holes, plated barrels and silkscreen text, and the board view measures in millimetres. It also carries mission 1625's clients for TypeScript, Rust, Java and C++, and serves gRPC beside Connect. It is a minor release, since it removes the IR's copy of the layer stack. The Breaking section names it and its replacement.

## Breaking

- **`ir.Design.stackup`, `ir.Stackup` and `ir.StackupLayer` are removed** (PR 1678, issue 1660). Field 10 is reserved. The board's stack lives only in `geom.BoardGeometry.stackup`, which every board reader fills. Migration: read the stack from the board geometry (`formats.Loader.BoardGeometry`, or `GetBoardGeometry` on the wire). `agni stats` on an IPC-2581 file no longer prints `stackup layers:`, and `agni stackup` prints the stack.
- **A KiCad pad that lists only paste or mask layers is no longer a pad** (PR 1680, issue 133). It leaves `ComponentPlacement.pads`, so the board view, the stack view's blocks and the pick areas stop drawing it. Of the samples, Jetson had 52 such pads, Cynthion 59 and MNT Reform 60.

## Added

### The board in 3D

- **Each part stands on the board in the stack view** (PR 1644). A part's block is the hull of its courtyard, fab outline or pads, at the height its file states, or at a default height that the view marks.
- **KiCad part heights from each footprint's STEP model** (PR 1681, issue 1652). The reader applies the footprint's model scale, turn and offset, and measures how far the model reaches above the pads. `--model-path`, `model_paths` in `agni.yaml`, `AGNI_MODEL_PATH` or KiCad's own `KICAD<n>_3DMODEL_DIR` names KiCad's library folder. `BoardGeometry.unread_models` lists each model that gave no height, and why. Glasgow's 213 heights match kicad-cli's export within 0.05 mm.
- **Altium, Allegro and ODB++ parts at their stated heights and outlines** (PRs 1658, 1666, 1667 and 1671). ODB++ package outlines, Altium's component bodies and Allegro's place-bound outlines shape and size each block.
- **Altium and Allegro layer stacks** (PRs 1661 and 1662). Altium's comes from Board6, and Allegro's from the board's cross-section. ODB++ jobs that Altium and Allegro wrote read their stacks too (PR 1675).
- **A Board look beside the layer look** (PR 1655). Parts take a colour by class, and the board reads like its maker's 3D view.
- **Holes, barrels, the board edge and text in the stack view** (PRs 1659 and 1673). Holes cut through each slab, a click picks a plated barrel, the edge is walled, and silkscreen text draws on each face, hidden where a part's block covers it.
- **The engine places the stack in depth** (PR 1674), so every front end draws the same stack.
- **Measure on the board in millimetres** (PR 1682, issue 133). A cursor readout and a point-to-point distance work in both renderers and snap to a pad.
- **parasdr's board outline from a package definition's graphics** (PR 1672).
- **A dimension oracle for the board render** (PR 1680, issue 133). kicad-cli's IPC-D-356 and GenCAD exports hold every drawn KiCad pad's centre and the board outline to the tool's own numbers.

### Serving and clients

- **Clients for TypeScript, Rust, Java and C++** (PRs 1646, 1647, 1648 and 1649), each with a replayer for the recorded wire fixtures and an example. `make exercise-clients` checks every client against the CLI (PR 1645).
- **gRPC over HTTP/2 beside Connect, on the same port** (PR 1640).
- **A board's geometry, a page at a time** (PR 1654). `GetBoardGeometry` pages a board to stay under a gRPC client's default message limit.
- **The server says what it is, and recovers a snapshot** (PR 1642). `make proto-check` holds the protos to the last release tag with `buf breaking`.
- **The engine answers how a board view follows a selection** (PR 1670), and the viewer's highlighting has a server twin (PR 1677), so another front end follows and highlights the same way. `build/front-end-rules.md` writes down what a front end decides.

## Changed

- **The viewer imports its generated code from the TypeScript client** (PR 1663), so the viewer and the client share one generation.
- **`agni emit --format ipc2581` writes the board's stack** (PR 1678), and its stated total matches the sum of its layers.

## Fixed

- **The stack tests after two PRs crossed** (PR 1676).
- **The walk no longer builds its own Windows binary**, since v0.7.0 ships one (PR 1641).

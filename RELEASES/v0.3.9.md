# v0.3.9

v0.3.9 lets an agent drive the viewer tabs a reader already has open, and lets a reader ask that
agent a question from the tab. It also gives the viewer a guided review tour that a reader takes
themselves. Every change is additive, the rooms are off unless `agni serve` is started with
`--viewer-rooms`, and everything in v0.3.6's notes holds, including its descriptor migration.

## Added

- **An agent drives open viewer tabs** (PR 1174, #1154). `agni serve --mcp --viewer-rooms` embeds a
  relay at `/relay/` and a room bridge on `/mcp`. Each viewer tab joins the room of the design it
  shows and offers the six `ViewerPageService` methods as tools (`viewer_get_location`,
  `viewer_show_sheet`, `viewer_locate_verdict`, `viewer_select_finding`, `viewer_locate_entity`,
  `viewer_apply_location`), beside the bridge's `list_pages`. A call names its design, and goes to
  the tab named by `page` or else the one the reader looked at last. A tab takes calls only once its
  reader ticks "Let agents drive this tab", which is per tab, off by default, and kept across a
  reload. It works on the stateless 2026-07-28 MCP wire as well as the session one.
- **A reader asks the agents a tab lets in** (PR 1175, #1173). With the switch on, an Ask box beside
  it sends the reader's question with the tab's location and selection, and the tab reports what the
  reader selects. An agent hears both with `next_request{design}` on either wire, and `list_pages`,
  `attach` and `pair` take `design` the way the `viewer_*` tools do. `examples/embed-viewer/README.md`
  walks through a demo of it.
- **A review tour of the viewer** (PR 1179). `?tour=review` on a viewer page starts nine steps: run a
  checklist, run the checks, look at a finding, open a query set, click into an answer, ask a
  follow-up, select a block, ask about it, and save the checklist page. Each step dims the page around
  the controls it needs, brings its panel forward, offers Show me, and advances when the viewer
  reports the action done, never on a click it infers. The viewer reports those actions as named
  events on its page bus (`web/src/viewerevents.ts`), which tsappkit 0.7.7's `Tour` follows.

## Changed

- **`make exercise-browser-review` runs headed, as the review tour** (PRs 1177, 1179). A developer
  running it takes the tour in a visible Chrome while the walk checks each result against the CLI.
  `STEP_BY_STEP=0` has the walk take the tour itself, and `HEADED=0` runs it headless, which is how
  a script or an agent logging the mission runs it. Headless the walk acts through the tour's holes,
  so in the gate a step whose control is unreachable, or whose action reports no event, fails it.

## Fixed

- **A viewer tab answers the room bridge alone** (PR 1175). In PR 1174 a page holding a valid room
  token for the same design could call another tab's tools directly, past the reader's switch. The
  tab now answers only the bridge's relay subject, which no page token can claim. This shipped in no
  release, since both PRs landed after v0.3.8.

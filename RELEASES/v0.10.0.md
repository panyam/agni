# v0.10.0

A design can now come from a private GitHub repo and open only for the people who can read that repo. A person signs in with GitHub, and the server keeps their GitHub token as their own connection. Every read of the design checks that connection: by name, by check, by snapshot, in a listing and by file path (PRs 1771, 1779 and 1791). A linked design also follows its history. It reads at any tag or commit of its source, moves when its branch moves by push webhook or poll, and keeps a report for each revision it was checked at (PRs 1773, 1777 and 1783). The designs page links a design from a mount (PR 1782). agni builds on Go 1.27.4 (PR 1793).

It is a minor release over v0.9.1, since it adds features. Every API it adds is new, and no existing Go API or proto field changes shape, so it has no Breaking section. Coming from v0.8.x, read [v0.9.0's notes](v0.9.0.md) first, since its Breaking section applies.

## Added

### Private repos, per person

- **A design linked from a private repo opens only for a caller who can read the repo** (PR 1771, issue 1728). The server needs `--auth tokens` for this. A person adds their connection with `agni connections add <id> --mine --github-token env:NAME`, and the server seals the token under the new `--connections-key`. `Design.access_sources` names the repos that decide who can read the design. A server without `--auth` records the private repo on each linked artifact, so the design is guarded once `--auth` is turned on.
- **Sign in with GitHub, through a GitHub App** (PR 1779, issues 1772 and 1776). `agni serve --github-client-id`, `--github-client-secret` and `--github-allow org:acme` add "Sign in with GitHub" to `/signin`. `agni login --remote` signs in from a terminal through GitHub's device flow, and `--public-url` names where GitHub sends the browser back. The server mints the person a token for `github:<login>` and keeps their GitHub token as their own connection. Deleting that connection revokes a token the server got by signing the person in, and only deletes a token the person pasted.
- **Each person's connection ids are their own** (PR 1791, issue 1778). bob can keep an `alice-gh` while alice keeps hers. `connections/<id>` names the caller's own connection before the server's, and a person can't take a server connection's id. A mount reads only through a server connection.
- **`agnids serve --connections-key`** checks each caller's own connection under `--auth`, as `agni serve` does, so a private mount opens in agnids for the people who can read its repo (PR 1791). agnids reads the connection records and sealed tokens and never writes or refreshes them. Without the flag, `--auth` still hides every private mount, and agnids leaves each mount's folder out of `ListMounts`.
- `ListMounts` and `GetMount` leave out a private mount's root, source, ref and commit for a caller who can't read its repo, and set `Mount.source_hidden` (PR 1779).

### A linked design's history

- **`agni designs revisions --tags` and `--commits`** list the linked repo's tags and a branch's commits as revisions, read or not (PR 1773, issue 1725). A public repo's mount lists its tags with no connection (PR 1794, issue 1788).
- **A design follows its branch or folder** (PR 1777, issue 1726). GitHub's push webhook arrives at `/hooks/github`, signed with the secret `agni serve --github-webhook-secret` names. `--poll 5m` asks each followed branch or folder on a timer instead. `agni designs update --on-source-change mark` keeps a design at its files and notes the newer commit as `ArtifactSource.newer_version` until a person syncs. `agni mounts webhook` creates the repo's push webhook through the mount's connection (`CreateMountWebhook`). A design's page in the viewer names each artifact's source, with a Sync button beside a newer version.
- **Reports at a revision** (PR 1783, issue 1774). `agni reports create bb@1.1.2` checks a design at a revision, and `Report.revision` names the revision each report read. The viewer's compare picker offers the revisions the server has read, and a report names the commit each artifact was read at (`Report.source_versions`).
- **The designs page links a design from a mount** (PR 1782, issue 1727), at a branch, tag or commit, and moves it to another ref later.

## Changed

- **Revisions are named.** A link names its revision by the ref every linked artifact is pinned at, and a ref names one revision. When a write moves a design, the server drops each revision nothing names: one that isn't current, has no ref, and is on no report (PR 1783).
- **A server with `--auth` deletes expired tokens** at startup and daily (PR 1791).
- **Go 1.27.4** (PR 1793, issue 1790). Every module's `go` line and the images' `golang` base move together. gosec moves to v2.30.0, since v2.29.0 under Go 1.27 skipped its SSA rules without reporting it.
- **Dependencies.** goapplib v0.7.25 and oneauth v0.3.14 (PR 1794). servicekit v0.2.4 (PR 1782). Go 1.26.11, brotli v1.2.7 and klauspost/compress v1.20.2 on the way there, which fix four advisories govulncheck reached from both shipped modules (PR 1785, issue 1786).
- **A folder mount names its version from its files' sizes and modification times**, so a sync of an unchanged folder reads no file (PR 1779).

## Fixed

- A person checked before they add their connection is no longer refused for a minute afterwards (PR 1779).
- `GetDocument` on a design the caller can't read answers `permission_denied` rather than `invalid_argument` (PR 1791).

## CI and the gate

- CI uses panyam/ci-actions v0.1.2 (PRs 1785 and 1787, issues 1780 and 1784). The browser jobs run the runner's own Chrome and download no Chromium. The browser suite and scripts launch the browser `CHROME_PATH` names, when it is set.
- The browser shards restore Go's build cache from main's newest run, so the wasm build and the agni binary compile only what changed (PR 1787). The browser suite runs as five shards rather than ten, which takes about 30% less runner time (PR 1792).
- The image builds cache only their final layers, which keeps them from filling the Actions cache (PR 1793, issue 1789).
- `make web-test` no longer fails at random with every test passing. Two unit test files left sheet views running, and a view's park timer fired after jsdom had gone (PR 1797, issue 1795).

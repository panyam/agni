# v0.11.2

A team running agni in its own network can now declare what a server holds and how it runs, in two files the server reads at every start. `agni serve --bootstrap` makes the connections, mounts, packs, designs and projects a file names, so a pod that comes back with an empty volume holds its boards again (PR 1852). `agni serve --config` reads serve's flags from YAML, and the Helm chart passes that file alone (PR 1856). A stored design now reads its folder's `design.yaml` the way `agni check <folder>` does, whether it was pushed, added from a mount or linked. It keeps the companions the descriptor declares, reads the entry it names and runs its intent (PRs 1855, 1859, 1863 and 1866). `agni designs add` can be scripted, since it keeps every board it can and a second run can skip or update (PR 1865).

It is a patch over v0.11.1. No exported Go API and no proto field changes shape, and the protos only gain fields. Coming from v0.10.x, read [v0.11.0's notes](v0.11.0.md) first, since its Breaking section applies.

## Added

- **`agni serve --bootstrap FILE` declares what a server holds** (PR 1852, issue 1808). The file names connections, mounts, packs, designs and projects, and the server makes them at every start. An entry that already matches is left alone, one whose source moved is linked again, and one that fails is logged by name and retried with backoff. `/readyz` answers 503, naming each failed entry, until every entry applies, and the chart's readiness probe moves to it. A stored design, pack or project the file doesn't name is kept and logged, and `prune: true` deletes it. The chart takes a `bootstrap:` value, and the compose bundle takes `AGNI_BOOTSTRAP`.
- **`agni serve --config serve.yaml` reads serve's flags from a YAML file** (PR 1856, issue 1853). Each key names a flag, and sections nest, so `github: {client_id: x}` sets `--github-client-id`. A flag on the command line wins over the file. An unknown key, two spellings of one flag or a value the flag refuses stops the server before it listens, naming the key. The chart renders `serve.yaml` into the `agni-serve` ConfigMap with the bootstrap folded in, and its new `serve` value adds settings the chart doesn't set itself.
- **`agni designs add` keeps what it can** (PR 1865, issue 1860). `AddDesignsRequest` gains `allow_partial` and `on_exists` (fail, skip or update), and `AddDesignsResponse` gains one `AddResult` per proposal, saying whether it was added, updated, unchanged, skipped or refused, and why. The CLI prints `refused <folder> <reason>` for each refused board and exits 1 after keeping the rest. `--only` narrows what `--yes` keeps, and `--skip-existing` or `--update` lets a second run succeed.
- **A guide section tries agni on a new install** (PR 1850, issue 1805). `guide/deploying` walks a team through copying the public Jetson baseboard into its GitHub, pushing the example project as a pack, and linking and reviewing the board, and says what the review shows.

## Fixed

- **A stored design keeps the companions its `design.yaml` declares, and reads the entry it names** (PR 1863, issue 1858). An ODB++ board and an EDIF schematic export declared together used to lose the schematic on `designs push`, and `designs add` refused the folder as two designs. The design's record now keeps the declared entry's artifact, so the stored design reads the board as the folder does, rather than the schematic its type order prefers. Linking the declared entry records it the same way.
- **A linked design keeps its `design.yaml`'s intent, and a stored design's check runs it** (PR 1859, issue 1854). `agni check designs/<id> --remote` lets the server build the design's catalog, so `--rule` names go as written. `--tag` on a stored design under `--remote` is refused, as under `--pack`.
- **`agni designs add` keeps the intent a board's `design.yaml` declares** (PR 1866, issue 1864). `--update` stores a changed intent though no file the design holds changed, and an intent that doesn't parse refuses the board.
- **A refused board's reason names a missing file by its mount URI** (PR 1866). It used to show the folder the mount serves from on the server.
- **A link of a declared KiCad root sheet takes its child sheets and project** (PR 1855, issue 1851), the files a push of the folder takes. The Review panel offers the checklists of the pack a design is viewed under.
- **A project whose `project.yaml` doesn't list its `profiles/` or `params/` folder says so** (PR 1862, issue 1861). `check`, `review`, `serve` and `packs push` each print one note naming the folders and the lines to add, where the project used to run without those tiers silently.

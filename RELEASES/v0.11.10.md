# v0.11.10

Several people can now share one `agni serve --mcp --viewer-rooms`, and each person's agent drives only that person's viewer tabs. Before this release, a signed-in tab couldn't join its room, and every agent acted as one subject, `local`. v0.11.10 fixes both. It also lets a reader pair another person's agent with their tab, and lets an agent answer in the tab and propose a next step. It is a patch over v0.11.9. The proto change adds two methods and their messages to `ViewerPageService`, and no field changes.

## Added

- **`make exercise-viewer-rooms`** (PR 1904, issue 1900). It starts a server with two local accounts, ada and bob, and signs each into the viewer and onto `/mcp` with an agent. Each row checks one thing a person should see. It runs in `browser-test` on every push.
- **A reader can pair another person's agent with their tab** (PR 1908, issue 1903). "Pair an agent", beside "Let agents drive this tab", shows a code for ten minutes. The agent enters the code with the bridge's `pair` tool. Each paired agent gets a row with a Revoke button, and a revoke refuses the agent's next call.
- **An agent can answer in the reader's tab** (PR 1909, issue 1907). Two new page tools come from `ViewerPageService`.
  - `viewer_show_answer` puts the agent's text under the Ask box, with a button for each net, part or pin it names. The text is drawn as plain text.
  - `viewer_propose` shows a card with Accept and Dismiss and returns a proposal id at once. The reader's click reaches the tab's agents as the page event `page.proposal_answered`, with the id, `accepted` or `dismissed`, and the action. The server declares the event's schema, so a tab from another build can't change it.
  - Both are refused with `failed_precondition` on the postMessage embed transport.
  - `examples/viewer-agent` is a scripted agent that hears a question, queries the design's parts, shows them, and highlights R1 when the reader accepts. Its README covers the same loop with Claude Code through `rooms-channel`.

## Fixed

- **A signed-in tab joins its design's room** (PR 1906, issue 1901). The auth gate now passes `/relay/` through, and the relay checks its own token. The gate used to put the session cookie in the `Authorization` header, which the relay refused.
- **Each signed-in person's agent drives only that person's tabs** (PR 1906, issue 1902). `JoinViewerRoom` mints a tab's relay token for its reader, such as `local:ada`. Under `--auth`, `/mcp` hands the caller to mcpkit as the call's claims, so a tab's switch agrees to its own reader's agents. A server that signs nobody in still acts for `local`.
- **A refusal on another person's tab says so** (PR 1908, issue 1905). It names the tab as another person's and says how to pair, rather than reading like a tab with its switch off.

## Changed

- **agni is on mcpkit v0.8.23**, Go modules and `@panyam/mcpkit-rooms`. v0.8.23 includes the gorilla/websocket fix for advisory GO-2026-6278.

# v0.11.3

A server stopped while it was writing to its store could leave the write half-done. `agni serve` stopped its background work when it exited, but it didn't wait for any of it. Say a poll pass or a webhook sync was rewriting a design, the bootstrap was linking one, or a sweep was removing old uploads. Each of them could still be writing when the process ended. v0.11.3 makes the server wait for them. It is a patch over v0.11.2, with no change to an exported Go API or a proto.

## Fixed

- **`agni serve` waits for its background work before it exits** (PR 1870, issues 1867 and 1869). A poll pass, a webhook sync, the bootstrap retries, the token prune, Graph subscription renewals and the uploads and records sweeps each stop at their next read once the server stops, and the server waits until they have. A poll test had flaked on Windows over it, because its temp folder's cleanup found the store still being written.

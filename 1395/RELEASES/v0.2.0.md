# v0.2.0

The first release with notes.  `v0.1.0` and `v0.1.1` were tag-only, cut a month earlier at PR 122,
and everything below has landed since across roughly 300 merged pull requests.

The bump is a minor rather than a patch because the range adds four CLI commands, a format reader, a
public composition package, and a public `service/` tier, and because several proto and Go surfaces
changed shape.  Pre-1.0, breaking changes ride a minor; see Breaking below for the ones that need an
edit on your side.

The theme, if there is one, is that the engine got much better at saying what it did.  A check used
to print the problems it found and stay silent about everything else, which reads identically to a
check that never ran.  Now a rule states the set it considered, a passing verdict carries the value
that decided it, and a report links back to the proof.  Most of the rest is the machinery that made
that possible, plus the datasheet layer growing up enough to be worth asking questions of.

## Breaking

- **`check` exits 2 when a gate trips**, matching `review`.  A CI step that treated any non-zero exit
  as a crash will now report a tripped `--fail-on` as one.  Exit 1 stays "the command failed", 0 stays
  clean.  (PR 236)

- **`Eval` returns a verdict for every subject** instead of filtering down to failures.  An embedder
  that counted the returned slice to get a failure count now counts everything the rule looked at.
  Filter on the verdict's outcome.  The overlay example had exactly this bug and is fixed in PR 398.
  (PR 396)

- **The part number is a typed IR field.**  `ir.Component.mpn` and `ir.PartType.mpn` replace the
  canonical-attribute convention, and the convention is deleted.  Code reading an `MPN` attribute off
  the attribute map should read the field.  A new spelling now goes in `classify.MPNAliases` rather
  than into a reader.  (PRs 521, 519)

- **`Package.pin_count` is removed.**  Nothing read it.  `Symbol.pin_count` is untouched.  (PR 202)

- **`naming.Config` collapsed into a proto schema**, so the engine can import it rather than carry a
  parallel Go type.  (PR 384)

- **`Candidate` and `WorkItem` are protos**, not Go types.  (PR 272)

- **The fact registry is a composed value.**  Package-level registration still exists, but it is an
  append-only buffer and every read goes through a `*facts.Registry` the caller holds.  Installing no
  relation catalog still builds and still runs, leaving the fact base empty, so `Registry.Installed`
  is what separates that from a query that matched nothing.  (PRs 536, 538)

- **`core/review` no longer knows a query language.**  A manifest's inline query compiles through a
  registered `review.QueryCompiler`.  A binary that wants datalog must pull in `stdlib/reviewquery`,
  and one that does not gets a clear failure rather than silence.  (PR 537)

- **`net.nominal_voltage` is rails only.**  A signal net's level moved to its own relation.  A query
  binding `nominal_voltage` on a signal net now returns nothing where it used to return a number.
  (PR 275)

- **`examples/overlay` is `examples/extension`**, and `build/overlay.md` is `build/extending.md`.  A
  module that builds on the engine never overlaid anything, so the name was wrong.  No engine API
  changed with it.  (PR 565)

## Added

### Commands

- **`agni trace`** answers a connectivity question by showing the route it crossed, rather than
  returning yes and making you take its word for it.  The route has a wire form, a CLI rendering, a
  viewer panel, and a deep link, so a route worth looking at is a route you can send someone.
  (PRs 598, 610, 611, 614, 606)
- **`agni open <design>`** serves one design and prints its URL, minting the mount itself.  Because
  one process mints and serves, the `check --url-base` line it prints alongside cannot disagree with
  the server about what is linkable.  (PRs 468, 469)
- **`agni params <mpn>`** prints the `PartSpec` record a query answer cannot reach: the conditions a
  value holds under, the pin bindings, the provenance, and the verification state.  It needs no
  design, because a spec library is not one.  (PR 552)
- **`agni emit --format edif`** writes a netlist.  Getting it portable took four passes, since our own
  reader is forgiving enough that a round trip proves almost nothing.  See Readers below.  (PR 530)
- **`agni start`** scaffolds a project from a design file.  (PR 223)

### Verdicts, coverage, and reports

- **A rule states what it considered.**  Twenty rules in one pass, eight of which also say why they
  cannot decide, plus the structural, intent, profile, and operator rules.  (PRs 400, 395, 417, 444,
  416, 419, 422, 423)
- **A passing verdict states the value that decided it**, and a verdict's subject can be a tuple, so a
  rule about a relation between two parts names both.  (PRs 401, 404, 415)
- **`check --format html`** is a verdict report a person can read, and it implies `--verdicts`.
  `review --format html` is the checklist twin, question-major, in the manifest's order.  Both share
  `core/report/style.css`.  (PRs 399, 480)
- **Every verdict format links to its proof**, or to nothing at all with the reason printed.  A link
  names the design's declared entry and carries the revision it was read at, and the viewer checks
  that revision before it draws.  (PRs 414, 490, 492, 461, 479)
- **Coverage is stated by default.**  (PR 410)
- **"Could not decide" stopped counting as "found a problem."**  (PR 352)
- **A results document records which rules could not run**, and the Checks panel says so too.  A
  blocked-on-data check names the facts it needed.  (PRs 250, 246, 264)
- **Every rule says how to fix it**, not only what breaks.  (PR 393)

### Query surface

- **Five output formats**: `text`, `csv`, `json`, `markdown`, `html`, plus `--title`.  markdown and
  html carry the title, the design, and the query above the answer, so a saved view states the
  question it answers.  csv deliberately carries no preamble.  An empty result is never an empty
  artifact.  (PRs 520, 378)
- **Derived relations**: `;` splits clauses, `:-` names one, and an unanchored negation is rejected
  rather than quietly answered.  (PR 524)
- **`having` and aggregates**, so a group can be asked about rather than aggregation stopping at the
  reduce.  (PR 615)
- **`entity(name, kind)`**, the relation a name search ranges over, plus search mode in the query
  panel and a result cell typed by its row.  (PRs 339, 340)
- **A relation declares what its arguments denote** rather than it being read off the labels, and a
  fact cites every site it rests on rather than the first one.  (PRs 554, 553)
- **Walk from a result row, or from a pin**, whose identity does not fit in one cell.  (PRs 336, 346)
- Datasheet parameters project into the query surface in SI base units, with absence and dimension
  first-class in a `Value`.  (PRs 164, 166, 167)

### Projects, config, and the embedding surface

- **A root `agni` package** composes the engine.  `agni.New` returns an `Engine` holding one composed
  catalog and one registry, and refuses an empty fact base or an uninstalled built-in catalog, so a
  missing registration seam fails at startup instead of running with zero rules.  Two legitimate
  absences report through `Warnings()`.  This is the fix for the overlay example having run for
  months with no built-in rules at all.  (PR 559)
- **`service/` moved out of `internal/`**, so an embedder can serve its own designs and config through
  `ProjectStore` and `ProjectConfigLoader`.  `artifact` came with it, because `artifact.URI` is in the
  port signatures.  The rule holding it honest is unchanged: no `os`, no `path/filepath`, no transport
  imports.  (PR 543)
- **A project and a design are modelled**, a declared entry behaves, and an artifact is named by one
  URI instead of a `(mount, path)` pair.  Reviews nest under the project they were made for.
  (PRs 172, 179, 180, 181)
- **`agni.yaml`** carries the flags that only say where bytes are.  The CLI walks up from the working
  directory, then looks in `~/.config/agni/`, so `agni check mount://corpus/...` works from anywhere
  with no flags.  A project can declare it `extends` another's config, and symbol libraries are config
  a project declares.  (PRs 230, 227, 229)
- **Naming a design's entry reads its declared companions**, so all three spellings of one design
  resolve identically.  `--as-named` opts out.  (PR 529)

### Datasheet layer

- **A parameter binds to a pin**, so a multi-supply part stops collapsing into one row, and the pin
  tier reaches the query surface as `param.pin` and `param.pin_range`.  A connection is checked
  against the pin's own rating rather than the part's.  (PRs 200, 204, 205)
- **A parameter can state a constraint between two pins**, with rules that check the tracking bound
  against the design.  (PRs 234, 267)
- **A verification is keyed to the revision it was performed against.**  A parameter someone verified
  reports `stale` when the corpus moves, naming both revisions.  Staleness is decided on the content
  hash and never on the printed revision string.  (PRs 271, 284, 285, 281)
- **A proposed fact is refused unless its citation checks out**, and a run's unmet facts roll into a
  seeding work list.  (PRs 268, 270)
- **Pins and packages seed from pin function tables**, and a supply or ground pin can be typed from
  the vendor's own sentence.  (PRs 240, 287)
- **Search inside one datasheet**, with hits that resolve to a region.  (PR 266)
- The extraction workbench authors pins, packages and bindings, records who transcribed a value and
  against which revision, and got the schematic viewer's pan and zoom.  (PRs 208, 289, 297)
- A net's role carries the evidence that established it, and a datasheet's pin functions can classify
  it.  (PRs 282, 283)

### Readers

- **A Telesis reader** for the flat netlist format.  (PR 379)
- **EDIF emit is portable.**  Our reader resolves references after parsing the whole file, accepts any
  atom as an identifier, and reads a port reference as a pin designator when nothing maps it, so a
  writer leaning on all three round-trips perfectly and produces a file nobody else can open.  Four
  rules came out of it: libraries before the design node, a `portRef` naming the cell's port with a
  `portInstance` table carrying the pin, identifiers holding no character a reader rejects, and
  everything referenced also declared.  The properties are asserted over the emitted text, because a
  re-read goes back through the same forgiving reader and agrees with the writer whatever either does.
  (PRs 579, 585, 592, 594)
- **KiCad placement and bus rules pinned against `kicad-cli`.**  A symbol is rotated and then
  mirrored, where the shared transform composes mirror first, so a mirrored placement at 90 or 270 had
  its pins swapped onto each other's nets.  A bus vector crossing a sheet boundary carries its members
  with it; two buses meeting at a sheet pin pair off by bit position rather than by name.  None of it
  is visible in a net count: one demo board read 47 nets against KiCad's 47 while 19 were wrong.
  (PRs 601, 576, 586, 602)
- **A truncated s-expression parse is a failure**, not a small board.  (PR 575)
- **Placeholder ref-des identity** is one predicate across all readers, so an unannotated ref-des
  cannot claim a pin conflict, and a design reports the components its source has not annotated.
  (PRs 308, 310, 313, 314)
- **A board file states part numbers too**, and they reach the export rather than only the read.
  (PRs 587, 596)
- Designator-less symbols anchor to the nets they name, in every format, so the symbol that names a
  net is clickable.  (PRs 329, 332)
- A reader declares which diagnostics it computed, and the rule gates on that.  (PR 321)

### Web viewer

- A landing page at `/` that routes rather than browsing, a default dock layout that puts every panel
  on the board, and a way back from the viewer.  (PRs 318, 325, 322)
- **Click an entity in the drawing, get the query that asks about it**, and see what is already checked
  about the thing you picked.  (PRs 327, 342)
- The design tree hides folders and mount roots with no readable design, and prunes by what the client
  opens.  (PRs 316, 317, 319)
- Project resolution is visible, with a project bar and a config picker per kind.  (PRs 182, 184)

## Changed

- **A run's provenance is recorded relative to the design's mount, never the host path.**  Readers
  stamp whatever path they are handed, so the rename happens once after the read.  A new host that
  opens files by absolute path and leaves `SourceName` nil publishes the machine that ran it, which is
  what `--results-out` stored until this landed.  Note that a query's citation list is sorted, so
  anything changing the source string reorders committed captures.  (PRs 511, 244)
- **A tier the project already composes is not a request**, and supersession says so.  `--profile-path`
  naming the project's own directory used to double-load every profile rule.  `agni review` now reports
  what the run superseded rather than what the flags did.  (PRs 467, 484)
- **`intake` reads the `params/` its project declares.**  Reading the tier from its flag alone meant
  that inside a project the datasheet-gap section was absent rather than empty.  (PR 483)
- **`readDesign` resolves the design's project config** for the six commands no service mediates.  All
  six bypassed it, so a read silently used the built-in naming vocabulary and none of the project's
  declared symbol libraries.  (PRs 252, 251, 353)
- A malformed descriptor is fatal for the design it governs, rather than being read as an absent one.
  (PRs 307, 315)
- `check` can be pointed at a board.  (PR 231)
- A rename that also changed can be recovered behind `--rename-approx`, off by default because the pass
  assigns a best match rather than recovering a fact.  (PR 455)
- Where the viewer's assets live is `--web-dir`, a flag rather than a positional.  (PR 457)
- A broken query is reported instead of reading as a design with no defects.  (PR 557)
- An MDIO profile, so the PHY management bus is not the one open-drain bus nothing checks.  (PR 534)
- C21 narrowed to identity and connectivity, C25 added for run provenance, C26 for the wire-form
  guards, C28 for read-time provenance, C29 for the fact layer's independence, and C15 retired.  The
  constraint audit fixed two violations and turned eleven `Verify` blocks into actual tests, because a
  constraint nobody runs is a comment.  (PRs 376, 221, 385, 386, 514, 539, 542, 560, 568)

## Fixed

- Schematic text renders in Arial rather than monospace, sized from the drawing rather than from
  constants, with ref-des placed from its designator display, `textHeight` read as a line pitch rather
  than an em size, pin numbers and part names drawn, and a multi-line block anchored by its justify.
  (PRs 298, 302, 299, 300, 301, 303, 304)
- `render` asks the design where its sheets are, and says so when it comes up short.  (PRs 433, 365)
- `i2c-pull-up` follows the resistor's other end.  `decoupling-present` asks whether the net is a rail
  rather than only whether a supply pin declares itself.  `fet-vdss` claims only switching parts.
  (PRs 383, 413, 405)
- A rail the naming lexicon cannot classify is reported, instead of the run quietly seeing fewer rails.
  (PR 278)
- A profile's device-class host binding survives the wire form.  (PR 385)
- Findings-table cells wrap rather than widening the table, a many-sheet badge strip stops painting
  over it, and query result columns are equal and resizable.  (PRs 328, 337, 326)
- A finding that will not highlight explains itself, and stops losing the reader's place.  A finding
  carries the entities its message names.  (PRs 368, 362, 363)
- The rule-authoring guide had been publishing as a blank page.  (PR 394)

## Docs

- **A `learn/` section**: twelve chapters teaching what a hardware engineer knows, each ending in the
  rules that encode it, with EE1 through EE7 levels indexed and a schematic per chapter.  This is the
  axis the guide and tutorials do not cover, since `tutorials/` teaches the tool and assumes the
  domain, while a rule page explains the check and assumes the instinct.  (PRs 427 through 443)
- **Client-side search** over the built site.  (PRs 334, 335)
- **Glossary terms a page can use without re-teaching**, tagged at first mention, fifteen terms with a
  diagram each.  (PRs 446, 447, 454, 478)
- **A readability pass** over the whole docsite, with a figure for every `learn/` chapter and for the
  tutorial pages a generated capture does not cover.  (PRs 477, 481, 486, 487, 488, 496, 497)
- **Command output is generated rather than pasted.**  Roughly forty fences across the guide and
  tutorials became `agniRun` captures, each command paired with its own output, and the gate
  regenerates them rather than trusting them.  Every remaining hand-written `agni` line is
  parse-checked.  (PRs 238, 239, 243, 248, 470, 499, 500, 502, 505, 507, 513, 525)
- A guide page for design intent, the one authoring shape that had none, and the docs name the rule
  primitive so the YAML stops reading as a bolted-on format.  (PRs 573, 571)

## Build and gate

- **Sample boards are fetched, not committed.**  `make samples` pulls a pinned tarball from
  `panyam/agni-samples`, keeping this repo uniformly Apache-2.0.  There is no offline escape hatch by
  design: a test reading the corpus fatals rather than skips, because a corpus that silently fails to
  arrive turns its tests into tests that pass over an empty set.  One stamp per artifact, so `samples`
  and `samples-oracle` compose instead of deleting each other's work.  (PRs 572, 595)
- **The gate fails when committed generated code does not match the protos**, for both the Go and the
  TypeScript halves.  (PR 276)
- **Browser tests** for the handful of assertions that need real layout, including a sweep over every
  docsite figure.  (PRs 345, 498)
- Fixture copies are declared and checked to still be copies, and a run fixture hashes its tracked
  content rather than the working tree, so the gate that reads the commit and the gate that reads the
  working tree cannot disagree.  (PRs 515, 364, 593)
- The Makefile is the interface and takes no private paths.  Every workflow that only existed as a
  wrapper in a local Makefile is a target here.  (PR 458)

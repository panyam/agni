# v0.3.4

v0.3.4 serves agni's analysis over the Model Context Protocol, so a coding agent such as Claude Code
can ask a design questions and get back rows it can check, and it lets a query variable be bound to a
list. It is cut as a patch at the maintainer's call, although two changes below break a Go signature
or a behaviour a caller may lean on, which `RELEASING.md` would put in a minor release. Both are listed
under Breaking with what to change. Everything in v0.3.3's notes holds.

## Added

- **agni over MCP** (PR 1122). `agni serve --mcp` serves it over streamable HTTP at `/mcp`, beside the
  viewer and the Connect API, and `agni mcp` serves it on stdio for a client that starts the server
  itself (`claude mcp add agni -- agni mcp --mount tut=<folder>`). The query tools (`schema`, `look`,
  `values`, `query`, `explain`) come from jaala's MCP frontend, and agni adds `designs`, `check`,
  `trace`, `diff`, `design`, `checklists`, `review` and `query_set`, plus resources for the relation
  catalog, the library, the rules and the designs. Every answer opens with the question it answers,
  gives its rows as `Tabulate` lays them out with the file each rests on, and ends in a viewer link or
  the reason there is none. The guide is
  [Asking through an LLM](https://panyam.github.io/agni/guide/asking-with-an-llm/), and
  `examples/ask-over-mcp` drives it through an MCP client.
- **`make exercise-mcp-ask`** (PR 1127), mission #909's exercise. It asks five review questions of
  the Jetson baseboard (or `WALK_DESIGN=gateway`) through an MCP client and checks each reply's rows
  against the CLI's answer to the same request, its links against a 200, and its rows against what the
  design is known to hold. On Jetson the first question pays for the board read, about 535 ms, and the
  rest take 5 to 56 ms.
- **A query variable bound to a list** (PR 1127) answers for each value, as if the goal were joined
  with a relation holding exactly those values. It is `QueryValue.list` on the wire, `--bind` naming
  a variable twice, `bind: {n: [A, B]}` in a query set, the `bind` param repeated in a viewer link (one
  chip in the panel), and `agni.bindings({"n": ["A", "B"]})` in the Python client. A document spells
  it `?n in ["A", "B"]`.
- **The browser-review walk is a gated spec** (PR 1119), `web/browser/review-walk.spec.ts`, and
  `make exercise-browser-review` runs it alone, headed with `HEADED=1`. The guided walk now opens on an
  intro page and keeps its Next button on screen (PR 1124).

## Changed

- **`agni serve --addr host:0`** binds a free port and its banner names the port it got, so a script
  can start a server of its own and read the URL off the first line (PR 1127).
- **A diff answer over MCP links each revision**, since the viewer has no view of a diff yet (#1126).
- **The MCP server reads each design under its own lock**, so a question about one design never waits
  for another being read (PR 1127).
- **servicekit v0.1.6** (PR 1127), whose graceful shutdown cancels request contexts first, so a
  long-lived MCP or Connect stream no longer holds `agni serve`'s drain for the full timeout. jaala
  v0.1.87, mcpkit v0.8.2, protobuf 1.36.12 and Go 1.26.9 (PR 1122).

## Fixed

- **A saved report links to the design's entry** whichever name the client sent (PR 1123).
- **A KiCad label spelled with a colon reads as KiCad reads it**, datasheet pin names compare through
  `core/ident`, and a Run click that landed before a design opened is no longer lost (PR 1114).
- **Three false positives on the demo seeds** (PR 1116): a PTVS clamp counts as protection, a zero-ohm
  link joins a rail, and an outlet the board itself powers is not judged as a power entry.
- **The demo walk fails a row** when it cannot reach a design's page, rather than passing over it
  (PR 1112).
- **The query panel opens tall enough for an answer**, and the checks headers stay on one line
  (PR 1125).

## Breaking

- **A rule name the catalog lacks is refused** (PR 1127) by `check --rule`, `CheckDesign.rules` and
  `GetCheckReport.rules`, as `INVALID_ARGUMENT` with the nearest names offered, where it used to run
  nothing and answer an empty run that read as clean. Migration: name rules as `ListRules` or the
  docsite's rule catalog spells them, or take the name the error suggests. A rule that exists only under some config, such as `intent/exposure-declared`, which
  needs a declared exposure, belongs only on a run that has that config.
- **Go signatures for bindings** (PR 1127). `query.Bindings` (`map[string][]query.Value`) replaces
  `map[string]query.Value` in `query.NamedQuery.Bind`, `query.FormatBindings`, `query.BindArgs`,
  `query.Bind`, `service.BindingsProto` and `QueryService.RunSpecLibQuery`.
  `service.BindingsFromProto` and `service.QuerySetFromProto` now also return an error, for a list
  inside a list. Migration: wrap single values with `query.One(map[string]query.Value{...})`, and
  handle the new error. The wire is unchanged for a single value.

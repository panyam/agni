# v0.3.6

v0.3.6 gives `project.yaml` and `design.yaml` one schema in which every tier a run reads is named, and
a design names its project. It also lets the viewer drill into the relation catalog module by module,
pick a trace's endpoints from the design, and link each rule to its reference page. It is cut as a
patch at the maintainer's call, although the descriptor change makes every existing `project.yaml` and
`design.yaml` fail to load until it is migrated, which `RELEASING.md` would put in a minor release.
Breaking says what to change. Everything in v0.3.5's notes holds.

## Added

- **One descriptor schema** (PR 1139). A design can declare any section a project can, and its own
  layer goes on top of its project's, so a board kept under an older naming scheme carries its own
  `conventions:` and a board with a peculiarity adds a checklist that `agni checklists` and the viewer
  list beside the project's. A design's convention or intent replaces its project's, a checklist of
  the same name replaces the project's in place, and the files it names are read beside the
  project's. Only a design names its own files (`entry`, `companions`, `revisions`,
  `flatten_hierarchy`).
- **A source can name one file** (PR 1139), as `profiles: [profiles/can.yaml]`, as well as a folder,
  and a `mount://` URI as well as a path relative to the descriptor.
- **The relation picker drills module by module** (PR 1131). The Examples & relations drawer opens on
  the namespace's root, and choosing a module lists its members with their tiers. Choosing a member
  shows its typed signature, which argument types were inferred, a library member's definition, its
  reference page, and an Insert button that builds the call from the argument names the server now
  sends (`RelationEntry.args`). The picker asks under the open design, so a project's own library
  members appear beside the shipped ones.
- **Trace endpoints are picked from the design** (PR 1135). Each end of the Trace panel is a combo box
  over the open design's parts and pins, matching letters in order (`u13` finds `U13`, `U13.1` and
  `U1.3`) and a pin's datasheet name. Choosing a part lists its pins with their nets, and Properties
  offers a selected part or pin as trace from here or to here. A pin typed out in full traces as typed.
- **Each rule links to its reference page** (PR 1135), from a rule group in the Checks panel and from
  each rule in the Rules panel. A project's own rule has no page and gets no link.

## Changed

- **Nothing is read for its folder's name** (PR 1139). `profiles`, `params`, `symbols`, `lib` and
  `queries` are lists the descriptor writes, and a path that names nothing is a load error, so a
  moved `profiles/` folder stops the run, where it used to run the board without the team's profiles
  and say nothing. To run without a tier, delete its line.
- **A design names its project with `extends`** (PR 1139), as a project already named shared config,
  rather than being found by walking up from its folder. A design naming none while a `project.yaml`
  sits above it is refused as a forgotten `extends`. A design folder copied, mounted or dropped
  without its project fails with a message saying to bring the project's folder along or remove
  `extends` to read the design on its own.
- **A proposed `design.yaml` names its symbol libraries** (PR 1139), so a KiCad design proposed from
  loose files or a zip draws its externally referenced symbols, and a design proposed under a project
  extends it.
- **The viewer's analysis panels say what they mean** (PR 1134). A finding clicked in the Review panel
  opens the sheet it is drawn on and keeps a pin subject's pin, as a Checks click does. The Checks
  panel's "Press Run checks" leads, a net drawn on no sheet says so, a sheet tile shows no count before
  a run, and Coverage says profiles are matched by Run checks. WebGL shows only on a page opened with
  `?mode=webgl`. The project bar's "built-in only" toggle reads "ignore project config".
- **CI runs on Node 24 actions** (PR 1137), and Dependabot watches the workflow actions.

## Fixed

- **Two mounts no longer share a cached descriptor search** (PR 1139). The project store keyed the
  folders it found on the search root alone, so a second mount walked from its own root could be
  answered with the first mount's folders.

## Breaking

- **Every `project.yaml` and `design.yaml` must be migrated** (PR 1139). Migration:
  - In `project.yaml`, name each tier folder it relied on, as `profiles: [profiles]`, `params:
    [params]`, `lib: [lib]` and `queries: [queries]`. A folder no line names is not read.
  - In each `design.yaml` under a project, add `extends:` with the path to that `project.yaml`, as
    `extends: ../../project.yaml`, and `symbols: [symbols]` if the design has a `symbols/` folder.
  - Rewrite `extends: projects/<id>` in a `project.yaml` as the path to that project's descriptor, as
    `extends: ../house/project.yaml`.
  - The refusals that named the layouts from before agni 824 and 828 (`conventions.yaml`, `review.yaml` or
    `intent.yaml` beside a descriptor, the `checklist:` key, a section naming a file, intent's
    nine-form keys) are gone. Each still fails at its line as an unknown or malformed key.
- **A design folder without its project no longer reads on its own** (PR 1139). Mounting, copying or
  dropping it alone fails at load. Bring the project's folder along, or remove `extends` from the
  copy's `design.yaml` to read it as a design in no project.

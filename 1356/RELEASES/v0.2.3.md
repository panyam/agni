# v0.2.3

One change since v0.2.2. A server keeps each rule's check results, so asking again for a rule it has
already run on an unchanged design answers without running the rule.

## Changed

- **`CheckDesign` keeps each rule's findings and verdicts with the design's cached model** (PR 1041,
  agni issue 390). A rule the model has already run answers from that run, and only the rules it has
  not run are evaluated. An edit to any of the design's files, or a different convention, reaches a
  model with nothing kept. A request whose configuration cannot be identified keeps nothing, and
  under a work budget an inconclusive rule is not kept. On the Jetson baseboard a second check of the
  whole catalog spends 17 ms in the engine rather than 103 ms. The CLI checks once per process, so it
  never finds a kept run.
- **Findings of one rule that tie on subject keep the rule's own order.** `check.RunAll` now sorts
  stably, which is what lets kept and new results join as one run would. Where a rule reports one
  subject twice, as a clearance finding against two neighbouring nets does, the two rows may come out
  in the other order from v0.2.2.

# v0.2.4

The first release you can try on your own machine and report back from without sending any of the
design. It ships a compose bundle and `agni trial`, and moves more of what the viewer and the CLI
show onto the engine's own answers. Tagged a patch with output changes a gate may read, as v0.2.2
was.

## Added

- **A compose bundle for trying a release where the designs are** (PR 1058, agni issue 1057).
  `compose.yaml` and `env.example` are attached to this release, pinned to `v0.2.4`. `docker compose
  up -d` (or `podman compose up -d`) serves the viewer over a read-only `./designs` folder and keeps
  stored reviews in a named volume. `--profile datasheets` adds the datasheet workbench. The guide is
  [Trying agni on your own boards](https://panyam.github.io/agni/guide/trying-agni/).
- **`agni trial <design>`** walks a design through read, check, checklists, query sets, a trace and
  saving the report, and writes a report of counts, timings and the names of rules agni ships. Its
  type has no field for a net name, reference designator, part number, design name, path or error
  text, and a rule a project wrote is counted without its name. It prints a link that opens the
  report as a GitHub issue for you to read before submitting. The bundle runs it as its `trial`
  service.
- **A `looks wrong?` link on each finding in the viewer** (agni issue 858) opens an issue naming only
  the rule (when agni ships it), its severity, whether it was inconclusive, and the engine version.
  `ListRules` now says which rules ship (`RuleInfo.shipped`) and the engine's version.
- **A query that does not parse says where it stopped** (PR 1043). `RunQuery` attaches a
  `TextPosition` error detail, `RunQueries` sets `NamedQueryResult.error_at`, and the CLI and the
  viewer draw the engine's caret under the query.
- **`agni query --server <url>|self` prints a viewer link** that re-asks the query (PR 1053, agni
  issue 634). A query from a project set links by the set's name and the query's.
- **Each finding carries the id of the verdict it came from** (PR 1052, agni issue 485), so every link
  on a checklist page opens the proof it names, including rules whose verdict is keyed on something
  other than the finding's subject.
- **The Review panel scores a checklist where the engine keeps no store** (PR 1055, agni issue 931),
  so a checklist runs on the static demo and on a server started without `--review-store`. The page
  holds the run until you leave it.
- **Every page says when a read left hierarchical blocks out** (PR 1056, agni issue 717): the viewer,
  the check report and the checklist report, in the CLI's wording.

## Changed

- **A failed request under `--format json` writes the Connect error** (`code`, `message`, `details`)
  to stdout or to `-o`'s file (PR 1044). Before, stdout was empty. The command still exits non-zero
  and prints the text error on stderr.
- **The markdown check report counts an inconclusive finding as unresolved** (PR 1046), as the
  viewer already did, in its own section. A gate that counted warnings from the report sees one fewer
  per inconclusive warning. The viewer ranks an unrecognised severity worst, as the report does.
- **A bound value is spelled the way a query reads it** (PR 1042). jaala v0.1.62 reads a string with
  no escapes, so a bound pattern like `^U1\.?$` is now shown as written rather than with a doubled
  backslash.
- **`check`'s default coverage line prints the `--verdicts` footer's totals** (PR 1049), and `query
  --speclib` answers through the same projection a design query uses, so it reports column kinds and
  work.
- **The viewer asks the engine** for Properties' pin names and test points (PR 1048), for what a query
  set's tab sends (PR 1047), and holds one check run instead of four per-rule caches (PR 1051, 1054).
- **The image creates `/var/lib/agni/reviews` owned by `agni`**, so a named volume mounted there is
  writable. On v0.2.3 it came up owned by root.
- **jaala v0.1.62** (PR 1042).
